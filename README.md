# getip

Консольная утилита, которая находит IP-подсети сайта или программы и сохраняет их
в `<сайт>.bat` с командами для Windows:

```
route add 160.79.104.0 mask 255.255.254.0 0.0.0.0
route add 34.120.0.0 mask 255.252.0.0 0.0.0.0
```

А ещё проверяет, правда ли трафик программы идёт через VPN-туннель роутера, и умеет пускать
выбранные сайты и программы мимо VPN на самом компьютере.

## Установка

Одна команда в терминале (macOS и Linux):

```bash
curl -fsSL https://raw.githubusercontent.com/MoteoDimassi/getip/main/install.sh | sh
```

Эта же команда обновляет getip до последней версии (или выберите «Обновить» в меню). Нужен
Python 3.9+ — на macOS он уже есть (или ставится командой `xcode-select --install`).

## Запуск

```bash
getip                  # меню
getip claude.ai        # быстрое сканирование → claude.ai.bat
getip claude.ai -d     # глубокое: поддомены из сертификатов + опрос DNS
getip claude.ai -s     # слушать трафик браузера (нужен пароль администратора)
getip -A Claude        # отслеживать соединения программы
getip -C Claude        # проверить, идёт ли трафик программы через туннель роутера
getip -b               # маршруты мимо VPN: включить, выключить, удалить
getip -x youtube.com --for 1h   # заблокировать сайт на час (macOS, нужен пароль администратора)
getip -h               # все ключи
```

## Режимы

| Режим | Что делает |
|---|---|
| Быстрое сканирование | Опрашивает основные поддомены через 6 DNS-серверов, ~10 сек |
| Глубокое сканирование | Находит поддомены в журналах SSL-сертификатов и опрашивает их по кругу |
| Слушать трафик | Записывает серверы, к которым обращается браузер, пока вы пользуетесь сайтом. Находит и чужие домены сайта (CDN, оплата) |
| Отслеживать приложение | Записывает соединения выбранной программы напрямую, без DNS |
| Проверить приложение | Для каждого соединения программы показывает, куда его отправляет роутер — в туннель или провайдеру, и отмечает зависшие соединения |
| Мимо VPN | Находит подсети сайта или программы и направляет их через роутер в обход VPN на компьютере |

Каждый IP расширяется до подсети, которую анонсирует провайдер (данные RIPEstat).
Настройки — шлюз, `route -p`, точные `/32`, папка для файлов, подгонка окна — в меню «Настройки».

### Размер окна

Меню само увеличивает окно терминала, если подсказки в нём не помещаются, а при выходе
возвращает прежний размер (если вы не меняли его вручную). Окно только растёт — большое
окно getip не трогает. Это работает в Terminal.app и iTerm2. Терминалы, которые не умеют
менять размер окна (tmux, встроенные в редакторы, окно на весь экран), getip спрашивает
один раз, а дальше просто укорачивает подсказки под окно. Выключается в «Настройки →
Подгонять размер окна».

### Как работает проверка

Компьютер подключён к роутеру, роутер передаёт пакет дальше — либо в VPN-туннель, либо
провайдеру. getip делает трассировку до каждого адреса программы и смотрит этот второй
узел: шлюз провайдера он узнаёт по российским адресам, которые через VPN не ходят, а
всё остальное считает туннелем. Трассировка идёт через Wi-Fi или кабель, в обход VPN
на самом компьютере, поэтому путь через роутер видно, даже когда этот VPN включён.

Зависшее соединение — то, что несколько секунд висит в состоянии `SYN_SENT`: программа
стучится, а сервер не отвечает. Мимо туннеля это обычно блокировка. Такие соединения
видны, только когда VPN на компьютере выключен — иначе программа ходит через него.

В конце getip показывает адреса, которые идут мимо туннеля, и предлагает маршруты для них:
в меню их можно дописать в `<программа>.bat` клавишей `s` или скопировать клавишей `c`.

### Мимо VPN

Бывает, что VPN-приложение включается на всё устройство и не умеет делать исключения. getip
обходит это маршрутами: VPN забирает себе маршрут по умолчанию, но более точный маршрут главнее,
поэтому подсеть, направленная через шлюз роутера (`route -n add -net 104.16.0.0/13 192.168.1.1`),
идёт мимо VPN. Нужен пароль администратора.

В меню «Мимо VPN» два режима: сайт (адреса ищутся быстрым, глубоким сканированием или по
трафику браузера) и программа (адреса её соединений). Перед добавлением getip показывает
найденные подсети и отмечает крупные — они уводят мимо VPN и чужие сайты того же провайдера.

Все исключения — на экране «Маршруты мимо VPN» (или `getip -b`):

| Клавиша | Что делает |
|---|---|
| Пробел | отметить маршрут; на названии сайта или программы — все её маршруты |
| `a` | отметить все / снять отметки |
| `r` | включить или выключить отмеченные (если ничего не отмечено — то, что под курсором) |
| `Enter` | проверить сайт или программу под курсором |
| `⌫` (или `d`) | удалить отмеченные — с подтверждением |
| `x` | удалить весь список — с подтверждением |

Проверка (она же запускается сразу после добавления) пробует подключиться к каждому адресу: к сайту —
по HTTPS с его именем, потому что провайдеры часто обрывают именно шифрование. Для каждого адреса
она показывает:

- отвечает ли он мимо VPN;
- ушло ли соединение через роутер или всё-таки в VPN — так видно, даёт ли VPN-приложение себя обойти;
- куда роутер шлёт адрес дальше: провайдеру или в свой туннель.

Ещё проверка находит программы, которые держат соединения через VPN, открытые до маршрута (браузер
надо перезапустить), и показывает внешний адрес и страну по базе MaxMind — мимо VPN и через VPN.
Подсети, которые мимо VPN не отвечают, можно сразу выключить клавишей `o`.

Выключенный маршрут остаётся в списке, но его нет в системе — трафик снова идёт через VPN,
а включить его можно в любой момент. Системные маршруты пропадают после перезагрузки и смены
сети, поэтому список getip хранит сам, в `~/.config/getip/bypass.json`, и показывает, какие
маршруты сейчас действуют. Чтобы вернуть их, отметьте все клавишей `a` и нажмите `r`: если
какие-то включённые маршруты пропали, `r` сначала возвращает их, а выключенные не трогает.
Подсеть, которая нужна двум сайтам, убирается из системы, только когда она не нужна ни одному
включённому.
Маршруты работают по IP-адресам и только для IPv4. Если в VPN-приложении включена блокировка
трафика мимо VPN (kill switch), исключения могут не сработать.

### Блокировка (macOS)

Закрывает доступ к сайту или IP на этом Mac для всех программ — на время или навсегда.
В меню — пункт «Блокировка», из терминала:

```bash
getip -x youtube.com --for 1h      # сайт на час (срок: 30m, 2h, 1d)
getip -x update.example.com        # сервер программы — навсегда
getip -x 1.2.3.4 5.6.7.0/24        # IP и подсети
getip --blocks                     # что сейчас заблокировано
getip -u youtube.com               # снять блокировку (getip -u all — снять все)
```

- **Сайт** закрывается строками в `/etc/hosts`: сам домен, `www` и существующие популярные
  поддомены. Уже открытые вкладки могут работать до перезапуска браузера.
- **IP и подсети** закрываются встроенным брандмауэром macOS (pf), в собственном разделе
  `com.apple/getip` — системные правила и VPN не затрагиваются. Соединения с закрытым адресом
  pf молча отбрасывает, поэтому программа не получает отказ сразу, а ждёт до своего таймаута.
- Временные блокировки снимает фоновая служба `com.getip.blocker`, даже если getip закрыт;
  постоянные она возвращает после перезагрузки. Когда блокировок не остаётся, служба
  удаляет себя сама. Служба запускает копию пакета из `/Library/Application Support/getip`,
  принадлежащую root, а не файлы пользователя.

Закрыть доступ программе целиком так нельзя: macOS разрешает это только подписанным
сетевым расширениям. Для этого есть бесплатный [LuLu](https://objective-see.org/products/lulu.html).
Адрес сервера, к которому ходит программа (например, за обновлениями), можно подсмотреть
в режиме «Слушать трафик».

## Удаление

```bash
curl -fsSL https://raw.githubusercontent.com/MoteoDimassi/getip/main/install.sh | sh -s -- --uninstall
```

## Устройство

```
getip.py              запускалка: находит пакет и запускает его
install.sh            установка, обновление и удаление
src/getip/
  cli.py              командная строка
  interactive.py      главное меню и его экраны
  scans.py            режимы сбора адресов: быстрый, глубокий, трафик, приложение
  check.py            режим проверки туннеля
  bypass_menu.py      раздел «Мимо VPN»: сайт, программа, список маршрутов
  block_menu.py       раздел «Блокировка» и ключи -x, -u, --blocks
  collector.py        копит IP и подсети, из которых получается .bat
  tunnel.py           куда роутер отправляет адрес: в туннель или провайдеру
  bypass.py           маршруты мимо VPN: список исключений и таблица маршрутов системы
  block.py            блокировка: /etc/hosts, брандмауэр pf и фоновая служба launchd
  connections.py      соединения программ по данным lsof
  lookup.py           DNS-запросы, crt.sh, подсети RIPEstat
  domains.py          разбор адресов сайтов
  routes.py           чтение и запись .bat
  config.py           настройки (~/.config/getip/config.json)
  update.py           проверка и установка обновлений
  term.py             вывод, клавиши, перетаскивание папок
  widgets.py          меню, список с галочками, строка-спиннер
  texts.py            названия и описания режимов
  style.py            цвета
tests/                тесты
```

Модули сверху вниз: экраны (`interactive`, `bypass_menu`, `block_menu`, `cli`) пользуются режимами
(`scans`, `check`), а режимы — логикой. Логика (`domains`, `routes`, `connections`, `tunnel`, `bypass`,
`block`) ничего не печатает
и не зависит от терминала, поэтому её проверяют тесты. Внешних зависимостей нет — только
стандартная библиотека Python, чтобы установка оставалась одной командой.

После установки код лежит в `~/.local/share/getip/getip`, а `~/.local/bin/getip` — это
та же запускалка `getip.py`. Обновление ставит пакет целиком через `install.sh`.

## Разработка

```bash
git clone https://github.com/MoteoDimassi/getip.git && cd getip
python3 getip.py           # запуск прямо из папки с кодом
python3 -m unittest        # тесты
./install.sh               # поставить версию из этой папки вместо скачанной
```

Новая версия — это `VERSION` в `src/getip/__init__.py` и такая же строка в `getip.py`:
по `getip.py` о новой версии узнают getip 1.3 и старше. Совпадение проверяет тест.
